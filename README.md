# ELEGOO_MARS_ONE-REBIRTH-WebUI-Controller-Project-
これは2019年製の初代Elegoo Marsの3.5インチタッチスクリーン式操作パネルが故障して操作不可能になり、リペアパーツの3.5インチ操作パネルが入手困難になってきたことをきっかけに、通常の操作パネルを取り外して迎い化した状態でもRaspberry pi zero w をChituboardのUART通信からWebUIで操作・印刷可能にした個人プロジェクトである。

また、通常の問題なしのMARS 3DプリンターもRasperry Pi zero W V1.1のWi-Fiを通じてWebブラウザーから操作可能にする。

実験：
・現時点ではRasperry Pi Zero （Wi-Fi機能無し）のモデルも同じくWi-FiアンテナUSBドングルを挿してWi-Fi化させてコントロールしようとする実験を行っているが、繰り返しRasperry Pi OS Lite 32-bit LegacyのOSクラッシュを起こして起動不可能になる現象に遭遇している｛実験中｝
問題はBluethoothとWi-Fiに関係していると思われる。

・現時点では正常運用可能なRasperry Pi zero W V1.1 以外のRasperry Piは検証不可能な状態であり動作保証保障外である。

＜プロジェクトに必要なもの＞：
・Elegoo Mars 初代 3D プリンター 本体
・Chituboard （現在開発中に使用しているメインボードは古いBタイプ）
・LM2596 電圧レギュレータ DCコンバータ (Dc/dc 12v>5v Step/down){RpiZeroWの電源用}
・MicroSDカード 2Gb以上 
（カスタムOSイメージは超軽量で約2.1GBしか使用しないため、4GB以上（4GB/8GB推奨）のMicroSDカードであれば完璧に動作します。）
・Rasperry Pi、LM2596コンバーターとChituboardを繋げるための電気線5本。
  接続：（5V, GND x2,TX, RX ）

＜仕組み＞：
Raspberry pi Zero W と Chituboard の UART通信でGcodeのやり取りをして制御を行う方式。

＜自己開発理由＞：
OctoPrintで制御を行おうとしたが、最終的にRaspberry pi Zero Wでは性能不足で上手えないという報告もあり、
結果、OctoPrintではサーバー起動の問題が発生して解決が出来なかった（解決の為の情報の深堀が面倒だったのであきらめた、
元々サーバーによる遠隔操作が目的ではなかった）ので同じ手法で異なるアプローチをとる実験を行った。
手順は以下の通り：


ーーーーーーーーーーーーーーーーーーーーーーーーーーーー

プロジェクトの整理：
・使用するのはRasperry Pi Zero W V1.1（かなり古い型番）

ーーーーーーーーーーーーーーーーーーーーーーーーーーーーー

・１２ｖから5Ｖ降下変圧器を挟む（注意：変圧器はRasperry Pi 本体に接続前に事前に電圧テスターで５Vに調整する必要がある、
さらにRasperry Pi に接続するUSBケーブルの差込口内の5V端子をテープなどで物理的な遮断をしなければRasperry Pi を破壊してしまうので注意が必要だ）

・MicroSDカード16㎇ 
（元々はOctoPrintを使用するつもりだったので8㎇でも容量不足だった為に16㎇を用意したが、今回の実験ではそこまでの容量は不要かも知れない）

・OctoPrintは廃止してRaspberry Pi OS Lite 32-bitを焼き直す（これから実行する）

・Rasperry Pi Zero Wに接続中のピン：
・ピン番号 4番（５V Power）＜Rasperry Pi Zero Wの電源供給用＞
・ピン番号 6番  (Ground) ＜Rasperry Pi Zero Wの電源供給用＞
・ピン番号 ８番 (GPIO 14 (UART TX))  <ChituboardからのUART通信用>
・ピン番号 10番 (GPIO 15 (UART RX))  <ChituboardからのUART通信用>
・ピン番号 14番 (Ground)  <ChituboardからのUART通信用>

ーーーーーーーーーーーーーーーーーーーーーーーーーー

使用するソフトウェアツール：
・コマンドターミナル（動作確認用の監視：PING）｛使うか使わないかはあなた次第｝

・PuTTY（WifiのSSH接続用）｛必須｝

・NetScan_Portable （Wifi接続中の機器IP調査用）｛ネットワークスキャンができるものなら何でも構わない｝

・Raspberry Pi Imager （MicroSDカードにOSイメージ書き込み用）｛必須｝

・Raspberry Pi OS 32-bit LITE Legacy版（MicroSDカードにOSイメージ書き込む）｛必須｝
   <Legacy版じゃなければ途中で問題になって起動しない現象が発生する>

・WinSCP（Raspberry Pi とWifi通信（SSH）でファイル転送したり編集したり中身を見ることが出来る。｛使うと便利｝
  （Raspberry Pi のMicroSDをPCに刺す必要がなくなるので超便利）

・Win32DiskImagerでカスタムOSブートイメージを作成する方が良い。
これまでの流れをバックアップすることで途中で繰り返してブートOSが壊れても簡単にやり直しが可能になる。
｛実験途中で何度もOSがぶっ壊れてOSをMicroSDカードにゼロからの焼き直しを経験しているため｝
  ＊注意：｛複数枚のMicroSDカードを持っていても、バックアップと復元用のMicroSDのメーカーとデータ容量が全く一緒じゃなければ問題が発生して起動できない現象を経験しているのでバックアップと復元用のカードのメーカーと容量は必ず揃えるようにすると良い｝
